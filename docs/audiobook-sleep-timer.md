# 听书定时关闭：产品与设计文档

## 1. 产品文档

### 1.1 功能目标

用户可以为听书设置自动停止条件，避免睡着后持续播放。定时支持按章节和按时间两种模式，两个模式互斥，不能同时生效。

当前弹层 UI 已完成，但倒计时目前只做界面演示。本方案用于补齐实际停止逻辑。

### 1.2 入口

```text
胶囊播放器
→ 听书设置
→ 定时关闭
```

定时关闭设置页包含：

| 区域     | 内容                           |
| -------- | ------------------------------ |
| 当前状态 | 剩余时间或剩余章节，右侧开关   |
| 按章节   | 播完本章、播完3章、播完5章     |
| 按时间   | 10分钟、30分钟、60分钟、90分钟 |
| 自定义   | 0-23 小时、0-59 分钟           |

### 1.3 定时模式

#### 按章节

从用户当前正在播放的章节开始计算：

| 选择     | 含义                               |
| -------- | ---------------------------------- |
| 播完本章 | 当前章播放结束后停止，不进入下一章 |
| 播完3章  | 当前章和后续2章播放结束后停止      |
| 播完5章  | 当前章和后续4章播放结束后停止      |

规则：

- 只有章节真正播放结束才减少剩余章节数。
- 暂停、切换阅读页、滚动正文都不减少章节数。
- 到达剩余章节数为 0 的章节边界时，定时关闭优先于“自动播放下一章”。

#### 按时间

从用户选择时开始按自然时间倒计时：

| 选择   | 停止时间         |
| ------ | ---------------- |
| 10分钟 | 10分钟后         |
| 30分钟 | 30分钟后         |
| 60分钟 | 60分钟后         |
| 90分钟 | 90分钟后         |
| 自定义 | 用户确认的时长后 |

规则：

- 设置后立即开始倒计时。
- 暂停播放不会暂停倒计时。
- 缓冲时间也计入倒计时。
- 切换页面、自动播放下一章都继续使用同一个倒计时。
- 到达 0 秒时停止当前音频，并清除定时状态。

### 1.4 自定义时长

- 范围：1分钟至23小时59分钟。
- `0小时0分钟` 不允许确认。
- 确认后替换之前的时间或章节定时。
- 取消后返回定时关闭页，不改变已有选择。

### 1.5 当前状态展示

时间型统一显示为：

- `剩余 MM:SS`
- 分钟数可以超过 59，例如 `剩余 90:00`

章节型：

- `剩余播放1章`
- `剩余播放3章`
- `剩余播放5章`

设置页中的“定时关闭”行显示当前选择；未设置时显示“未开启”。

### 1.6 开关与切换

| 操作         | 结果                                       |
| ------------ | ------------------------------------------ |
| 选择章节选项 | 切换为章节倒计时                           |
| 选择时间选项 | 切换为时间倒计时                           |
| 自定义确认   | 切换为自定义时间倒计时                     |
| 关闭顶部开关 | 取消当前定时，恢复默认连续播放和自动下一章 |
| 选择其他定时 | 直接替换之前的定时，不叠加                 |
| 定时到期     | 暂停音频，清除定时，播放器保留             |

### 1.7 媒体行为

定时到期后：

1. 暂停当前音频。
2. 保留当前章节、播放位置和音频缓存。
3. 清除定时状态。
4. 用户再次点击播放时可以继续听。

不关闭胶囊播放器，不销毁音频上下文。

### 1.8 生命周期

| 场景                 | 处理                           |
| -------------------- | ------------------------------ |
| 切换阅读页           | 定时继续                       |
| 进入后台继续播放     | 定时继续，依靠目标结束时间校准 |
| 回到前台             | 立即校时；已到时间则停止       |
| 自动播放下一章       | 定时继续                       |
| 用户主动关闭播放器   | 同时取消定时                   |
| 用户主动开始另一本书 | 取消原听书定时                 |
| 小程序进程被终止     | 定时不恢复                     |

### 1.9 不在本期范围

- 不同时支持多个定时条件。
- 不按实际朗读时长折算自然时间。
- 不在胶囊外额外展示悬浮倒计时。
- 不新增后端接口。
- 定时不跨小程序重启持久化。

### 1.10 验收标准

- 三种章节选项都在正确章节边界停止。
- 四种快捷时间和自定义时间都能按时停止。
- 自动下一章不会绕过定时关闭。
- 暂停后时间型定时继续倒计时。
- 关闭开关后只取消定时限制，音频继续播放并恢复自动下一章。
- 发出新定时会替换旧定时。
- 到期后播放器仍可继续播放。

## 2. 设计文档

### 2.1 状态模型

定时状态放在 `useAudiobook` 单例中，跨页面、跨章节共享。

```ts
type SleepTimerState =
  | {
      mode: 'off'
    }
  | {
      mode: 'time'
      durationSeconds: number
      endAt: number
    }
  | {
      mode: 'chapters'
      totalChapters: 1 | 3 | 5
      remainingChapters: number
    }
```

页面只读取状态并发送设置/取消操作，不自己维护独立倒计时。

### 2.2 对外接口

```ts
interface AudiobookTimerController {
  sleepTimer: ComputedRef<SleepTimerState>
  setSleepTimerByMinutes: (minutes: number) => void
  setSleepTimerByChapters: (chapters: 1 | 3 | 5) => void
  cancelSleepTimer: () => void
}
```

内部还需要章节结束钩子：

```ts
function shouldContinueAfterChapterEnd(): boolean
```

`advanceTextPlayback()` 在自动进入下一章前必须调用该钩子。

### 2.3 时间型定时

不使用简单的递减计数器作为真实数据源，而是保存绝对结束时间：

```ts
endAt = Date.now() + minutes * 60 * 1000
```

原因：

- 小程序进入后台时定时器可能被节流。
- 每秒递减会因暂停、卡顿累积误差。
- 使用 `endAt` 可以直接校准剩余时间。

刷新：

- 前台每 1 秒更新一次界面剩余时间。
- `onTimeUpdate` 中检查 `Date.now() >= endAt`。
- 页面重新显示或 App 回到前台时立即检查一次。

到期动作：

```text
检查 endAt
→ 清除 interval
→ activeAudioContext.pause()
→ sleepTimer = off
→ 提示“定时关闭时间已到”
```

### 2.4 章节型定时

章节定时与播放计划分离：

- TTS 的 `hasMore=false` 表示当前章节文本结束，不直接减少章节数。
- 进入下一章前调用章节结算。
- 当前章节播放结束后，`remainingChapters -= 1`。
- `remainingChapters > 0` 才允许调用下一章的 `start()`。
- `remainingChapters === 0` 时不发起下一章 TTS 请求。

流程：

```text
当前章结束
→ 读取 sleepTimer
→ 非章节定时：继续原有逻辑
→ 剩余章节减 1
→ 剩余为 0：暂停并清除定时
→ 剩余大于 0：自动播放下一章
```

### 2.5 与自动下一章的衔接

现有逻辑：

```text
当前章节 hasMore=false
→ resolveNextChapter()
→ start(下一章)
```

增加定时判断：

```text
当前章节 hasMore=false
→ shouldContinueAfterChapterEnd()
  → false：暂停，不请求下一章
  → true：resolveNextChapter()
             → start(下一章)
```

定时判断必须优先于下一章请求，避免停止后又发出无效的 TTS 请求和音频下载。

### 2.6 定时替换和取消

| 操作       | 内部处理                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 设置时间型 | 清理章节状态，保存 `endAt`                                             |
| 设置章节型 | 清理时间 interval，保存剩余章节                                        |
| 关闭开关   | 清理 interval 或章节计数，状态改为 `off`；后续章节边界恢复默认自动续播 |
| 播放器关闭 | 先取消定时，再释放播放资源                                             |
| 新书开始   | 先取消旧定时，再启动新会话                                             |

自动切换章节时不能调用“取消定时”逻辑。

### 2.7 UI 绑定

`AudiobookSettingsSheet` 不再维护本地演示倒计时，改为：

- 从 `useAudiobook` 读取 `sleepTimer`
- 选择章节时调用 `setSleepTimerByChapters`
- 选择快捷时间时调用 `setSleepTimerByMinutes`
- 自定义确认时调用 `setSleepTimerByMinutes`
- 顶部开关关闭时调用 `cancelSleepTimer`

剩余时间由全局状态计算，避免关闭再打开弹层后倒计时重置。

### 2.8 自定义时间校验

```ts
const totalMinutes = hours * 60 + minutes

if (totalMinutes <= 0) {
  uni.showToast({ title: '请选择至少1分钟', icon: 'none' })
  return
}
```

确认后按总分钟数设置，不保存“小时/分钟”的 UI 字符串，避免后续解析错误。

### 2.9 文案与提示

| 场景         | 文案             |
| ------------ | ---------------- |
| 定时到期     | 定时关闭时间已到 |
| 自定义0分钟  | 请选择至少1分钟  |
| 章节定时完成 | 定时播放已完成   |

提示只显示一次，不使用阻塞式弹窗。

### 2.10 验证用例

| 用例                 | 预期                                           |
| -------------------- | ---------------------------------------------- |
| 播放中设置10分钟     | 到点暂停，播放器保留                           |
| 暂停时设置10分钟     | 倒计时仍继续，到点清除定时                     |
| 设置播完本章         | 当前章结束时不请求下一章                       |
| 设置播完3章          | 当前章结束继续，第3章结束停止                  |
| 设置60分钟后自动跨章 | 跨章不重置倒计时                               |
| 自定义1分钟          | 从确认时开始计时                               |
| 自定义0分钟          | 拒绝确认并提示                                 |
| 时间型改成章节型     | 时间倒计时立即取消                             |
| 章节型改成时间型     | 章节计数立即取消                               |
| 关闭顶部开关         | 定时取消，音频继续，播完当前章后自动播放下一章 |
| 定时到期后点击播放   | 可以从原位置继续                               |
